# E1000 parse-error

SQL could not be parsed.

| Code | Name | Category | Default |
|------|------|----------|---------|
| `E1000` | `parse-error` | correctness | error |

## What it reports

The file contains SQL that sqlsift's parser can't read for the selected dialect.

## Example

```sql
SELEC id FROM users;
```

```text
error[E1000]: Parse error: Expected: an SQL statement, found: SELEC
  --> q.sql:1:1
    |
  1 | SELEC id FROM users;
    | ^
```

Fixed:

```sql
SELECT id FROM users;
```

## Notes

- Check `--dialect`: MySQL or SQLite syntax may not parse as PostgreSQL.
- Templated SQL (Jinja, dbt) and SQL embedded in other languages aren't supported.
- If the SQL is valid for your database, please [open an issue](https://github.com/yukikotani231/sqlsift/issues/new/choose). Meanwhile, `-- sqlsift:disable-file` or `ignore` skips the file.

## Configuring

```toml
# sqlsift.toml
[rules]
parse-error = "warn"   # or "off"
```

Or for a single line: `-- sqlsift:disable E1000`. The examples use the schema on the [Rules](index.md) page.
