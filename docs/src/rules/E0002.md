# E0002 column-not-found

Referenced column does not exist in table.

| Code | Name | Category | Default |
|------|------|----------|---------|
| `E0002` | `column-not-found` | correctness | error |

## What it reports

A column reference doesn't match any column of the tables, views, CTEs or subqueries in scope.

## Example

```sql
SELECT naem FROM users;
```

```text
error[E0002]: Column 'naem' not found in table 'users'
  --> q.sql:1:8
    |
  1 | SELECT naem FROM users;
    |        ^^^^
    = help: Did you mean 'name'?
```

Fixed:

```sql
SELECT name FROM users;
```

## Notes

- Typos, and columns renamed or dropped by a migration. This is the most common way a schema change breaks a query in another file.
- Columns of a subquery or CTE that the subquery doesn't select.

## Configuring

```toml
# sqlsift.toml
[rules]
column-not-found = "warn"   # or "off"
```

Or for a single line: `-- sqlsift:disable E0002`. The examples use the schema on the [Rules](index.md) page.
